# Experimental grouped ragged QPN full-model performance A/B

- Branch `qpn/performance-first`; V100 sm_70 and CUDA 12.8; compile option `STRATA_QPN_PREFILL_EXPERIMENTAL=ON` remains off in normal builds.
- Existing `STRATA_QPN_PREFILL_EXPERIMENTAL=1` and `STRATA_QPN_PREFILL_FUSED_GU=1` are both required for the new `STRATA_QPN_PREFILL_BATCHED=1` experiment. The old fused-per-expert QPN and original MMQ fallback remain intact when the new flag is absent.
- Existing `qpn_partition_rows` and `qpn_entire_group` decide exclusive ownership of up to 16 experts with **17–32 actual routed rows**. All counts and bounds are checked before the compute stream is issued. No expert group is executed in both QPN and MMQ.
- Each group is packed to contiguous **32 FP16 rows per expert** from the original per-token activation and exclusive routing positions. Padded rows are zero. One `projection_batch` computes the 1280-column gate+up projection; one ragged fused SiLU kernel handles per-expert tail scales and FP16 staging; one `projection_batch` computes down; one masked scatter writes the actual rows to their original absolute slots. The unchanged MMQ down-row-scale kernel writes per-row down scales for combination. One group therefore uses five per-group launches plus unchanged guard/scale operations instead of ~4–5 launches per expert.
- Batched scratch is allocated only on explicit opt-in before CUDA graph capture, independent of cache slots, weights and model pack. Scratch includes padded X, H, GU and down output.
- Safety: standalone reusable batch primitive [V100 run 40966227319](https://github.com/mylordmonkeyman/Strata-V100/actions/runs/40966227319) passed exact output parity, changed-input replay, 256-byte guards, sampled memcheck and racecheck. This does **not** qualify the new end-to-end full-model path.
- New isolated workflow A/B/B/A runs `qpn-fused`/`qpn-batched`/`qpn-batched`/`qpn-fused` on the same pinned private model, prompt, 768 staged prefill, routing policy and static weight residency. It records aggregate prefill latency, actual QPN selected groups, first-logit KL/L2 and argmax, without uploading prompts, activations or logits.
- The `--performance-only` option defers the existing first-logit acceptance threshold for a performance diagnosis **without claiming quality qualification**. Execution failure, nonfinite logits, no QPN execution, or missing measurements remain hard failures. A model speedup claim requires matched GPU data and a separate MMQ control run; synthetic 1.68x does not establish full-model speedup.
- Do not enable default dispatch, modify `main`, pack, cache, or runner privileges.
