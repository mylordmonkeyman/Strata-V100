# QPN T33–128 vs MMQ on pinned real-expert workload — V100 result (2026-10-29)

**Disposition:** Correct and sanitizer-clean, but performance is mixed. CUDA Graph replay is **2.19% faster** than matched all-MMQ, whereas ordinary execution median is **2.56% slower**, with substantial variation between six alternating rounds. Do **not** integrate these expert sizes into full-model inference based on this result alone.

- Branch `qpn/large-route-probe`, source commit `b3b29c62d8d270ae150ff2cad509e23af196ec72`, [successful run 40971421388](https://github.com/mylordmonkeyman/Strata-V100/actions/runs/40971421388), aggregate artifact **12941106033** (downloaded/inspected).
- SHA-verified *real private 16-expert weights and activation capture*: 1,100 exact routed rows, 44,237,056 distinct compressed expert weight bytes (versus V100 6,291,456-byte L2). Private input bytes, source activation rows and raw outputs stay on runner.
- Exactly four 33–128-row experts selected for QPN: **40, 48, 60, 96 rows** (244 routed entries). Remaining **12 experts** stay with MMQ, including 187- and 508-row large experts. Both arms see identical offline expert permutation and all genuine routed rows; all-MMQ control uses the same permutation. Experimental `qpn_min=33` was run outside engine.
- Independent sampled GGUF FP64 oracle: all-MMQ relative L2 `0.0112966272`, mixed QPN/MMQ `0.00851350195`, mixed-vs-MMQ `0.00487795224`; **numerical acceptance passed** for the standalone test. 32 oracle rows intentionally sampled, not exhaustive.
- Changed-input CUDA Graph replay matches ordinary output exactly for both arms; output-tail guard intact, finite outputs. Compute Sanitizer `memcheck` **0 errors**, `racecheck` **0 hazards / 0 errors / 0 warnings** on this sample.
- Six alternating CUDA-event rounds with ten completed workloads per round. Ordinary timings include host launch gaps; graph values isolate more GPU-side work but still include launch/replay and do not represent model TTFT.
